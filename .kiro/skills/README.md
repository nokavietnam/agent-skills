# Bộ Skills viết & review Blog cho AI

Bộ skills giúp AI trở thành người viết blog kỹ thuật chuyên nghiệp — bao trọn quy trình từ **nghiên cứu chủ đề/SEO → viết → review → đóng gói → tối ưu & phân phối** để tăng traffic tự nhiên. Nội dung nhất quán về giọng văn, cấu trúc, tính chân thật và chuẩn trích dẫn nguồn.

## Skill viết

| Skill | Dùng khi nào | Nội dung chính |
| --- | --- | --- |
| `blog-foundations` | **Luôn dùng đầu tiên** khi viết | **Tính chân thật & độ chính xác** (không bịa đặt, không suy diễn, không sai lệch, xác thực đa nguồn, **luôn tra cứu thông tin mới nhất tại thời điểm viết**), giọng văn, cấu trúc bài, SEO, **E-E-A-T & tránh bị Google đánh spam** (people-first content, giá trị gốc, tránh scaled content abuse), **chống đạo văn** (viết bằng lời của mình, ghi công, đạo văn code), formatting Markdown, trích dẫn & kiểm chứng nguồn, checklist xuất bản |
| `ai-news-writing` | Viết tin tức, tổng hợp, phân tích sự kiện/thông báo AI | Kim tự tháp ngược, 5W1H, kiểm chứng nguồn chính thức, xử lý benchmark, mốc thời gian |
| `backend-engineering-writing` | Viết bài kỹ thuật Backend (API, DB, cache, kiến trúc, performance) | Chuẩn code example, sơ đồ Mermaid, giải thích trade-offs, độ chính xác kỹ thuật, bảo mật mặc định |
| `ai-coding-tips-writing` | Viết mẹo/workflow lập trình với AI coding tool | Trình bày prompt trước/sau, nguyên tắc chung, rủi ro của AI (hallucination, bảo mật, review) |

## Skill review

| Skill | Dùng khi nào | Nội dung chính |
| --- | --- | --- |
| `blog-review` | **Luôn dùng đầu tiên** khi review | Quy trình review 8 trục (gồm **soi tính chân thật & độ chính xác**, **soi rủi ro bị Google phạt / loại khỏi search**, **soi đạo văn**), phân loại mức độ (🔴 Blocker / 🟡 Nên sửa / 🟢 Gợi ý), format báo cáo review chuẩn |
| `ai-news-review` | Review bài tin tức AI | Kiểm chứng nguồn chính thức, độ chính xác benchmark, mốc thời gian, phát hiện clickbait |
| `backend-engineering-review` | Review bài kỹ thuật Backend | Soi code như review PR, an toàn bảo mật, độ chính xác kỹ thuật, đủ trade-off, điều kiện đo benchmark |
| `ai-coding-tips-review` | Review bài tips lập trình với AI | Mẹo có kiểm chứng, ví dụ prompt trước/sau, nêu rủi ro AI, trung lập với công cụ |
| `system-design-review` | Review bài System Design | Yêu cầu trước giải pháp, capacity estimation, sơ đồ khớp mô tả, đủ trade-off, độ chính xác CAP/consistency |
| `low-level-design-review` | Review bài Low-Level Design (OOP) | Yêu cầu trước class, không God class, pattern đúng chỗ & đúng tên, tuân SOLID, bài kiểm tra mở rộng |
| `dsa-review` | Review bài DSA | Code chạy đúng trên edge case, phân tích big-O đúng & có giải thích, có trực giác + dry-run, đủ edge case |
| `ml-system-design-review` | Review bài ML System Design | Bài toán nghiệp vụ trước, chống data leakage & training–serving skew, metric đúng + A/B test, giám sát drift |
| `behavioral-interview-review` | Review bài phỏng vấn hành vi | Không khuyến khích bịa thành tích, STAR đủ 4 phần, ví dụ mẫu đánh dấu rõ, ngôi "tôi", lời khuyên hành động |

> Nhóm phỏng vấn & thiết kế giờ đã có skill review chuyên biệt; mỗi skill review đối chiếu đúng checklist mà skill viết tương ứng yêu cầu.

## Skill định dạng đầu ra

Lo phần **đóng gói bài ra định dạng đích**, dùng chung cho mọi loại bài, kế thừa nội dung từ `blog-foundations` + skill viết.

| Skill | Dùng khi nào | Nội dung chính |
| --- | --- | --- |
| `wordpress-publishing` | Chuẩn bị/đăng bài lên web WordPress | Gutenberg block vs Classic HTML, metadata (slug/excerpt/categories/tags/featured image), chèn code đúng cách (escape HTML), SEO Yoast/Rank Math, đăng qua REST API (Application Password, draft trước) |
| `markdown-authoring` | Xuất bài ra file .md/.mdx tùy chỉnh | Chọn flavor (GFM/MDX/Hugo/Docusaurus/Jekyll/Obsidian), front-matter YAML/TOML, TOC, callout/admonition, quy tắc Markdown sạch, tên file & thư mục đích |
| `math-formula-authoring` | Bài có công thức toán (DSA, ML, xác suất, capacity) | Delimiter đúng nền tảng (GitHub/GitLab, SSG, WordPress), escape ký tự dễ vỡ ($, \\, _, *, \|), inline vs display, render thử trước khi đăng |

## Skill chiến lược & SEO (tăng traffic)

Bao khâu **trước** và **sau** khi viết — nơi phần lớn traffic được quyết định.

| Skill | Dùng khi nào | Nội dung chính |
| --- | --- | --- |
| `blog-ideation-seo` | **Trước khi viết** — chọn chủ đề, nghiên cứu từ khóa | Keyword research bằng nguồn kiểm chứng được, search intent, quan sát SERP, topic cluster (pillar + cluster), xuất Content Brief cho skill viết |
| `title-headline-writing` | Đặt/tối ưu tiêu đề & meta title | Công thức tiêu đề theo dạng bài, tối ưu độ dài & CTR, ranh giới clickbait, xuất 3–5 biến thể để chọn |
| `content-optimization-distribution` | **Sau khi xuất bản** — tăng traffic | Content refresh bài cũ, internal linking & cluster, cứu bài tụt hạng, phân phối đa kênh, cross-post có canonical |

## Skill dạng bài (format)

| Skill | Dùng khi nào | Nội dung chính |
| --- | --- | --- |
| `tutorial-writing` | Bài hướng dẫn từng bước (how-to) | Prerequisites, kết quả cuối ở đầu, bước đánh số, code kiểm chứng, bước Verify, troubleshooting, HowTo schema |

## Skill chuẩn trình bày (hình ảnh & code)

| Skill | Dùng khi nào | Nội dung chính |
| --- | --- | --- |
| `image-diagram-authoring` | Bài cần ảnh, screenshot, hoặc sơ đồ kiến trúc/luồng | Alt text đúng cách, caption, sơ đồ dạng code (Mermaid/PlantUML), tính đúng của sơ đồ, che thông tin nhạy cảm, định dạng/nén ảnh (SVG/WebP), bản quyền/ghi công |
| `image-diagram-review` | Review phần hình ảnh/sơ đồ của bài | Soi alt text, sơ đồ khớp hệ thống thật & đúng chiều, screenshot lộ thông tin nhạy cảm, định dạng/nén, bản quyền |
| `code-snippet-standards` | Bài có nhiều code block cần trình bày chuẩn | Khai báo ngôn ngữ, code chạy được vs minh họa, độ dài & cắt gọn, tên file/đường dẫn, output & diff, không hardcode secret, ghi công code mượn |
| `code-snippet-review` | Review cách trình bày code của bài | Soi khai báo ngôn ngữ, code minh họa bị tưởng chạy được, output bịa, secret hardcode, dòng quá dài, ghi công code mượn/license |

## Skill chủ đề phỏng vấn & thiết kế

Chủ đề nặng lý thuyết, đánh đổi và chuẩn bị phỏng vấn. Áp dụng chồng lên `blog-foundations`; có thể kết hợp với skill dạng bài.

| Skill | Dùng khi nào | Nội dung chính |
| --- | --- | --- |
| `system-design-writing` | Thiết kế hệ thống quy mô lớn, luyện phỏng vấn SD | Yêu cầu (functional/non-functional), capacity estimation, high-level design + deep dive, sơ đồ, trade-offs (CAP, SQL/NoSQL, sharding) |
| `low-level-design-writing` | Thiết kế hướng đối tượng (OOP/LLD) | Yêu cầu → entities → class diagram, design pattern đúng chỗ, SOLID, bài kiểm tra mở rộng |
| `dsa-writing` | Giải thuật, lời giải bài toán coding, big-O | Phát biểu bài toán, trực giác, brute-force → tối ưu, dry-run, phân tích độ phức tạp, edge cases |
| `ml-system-design-writing` | Thiết kế hệ thống ML end-to-end | Đóng khung ML, dữ liệu & feature (chống data leakage), training vs serving, metric offline/online + A/B test, drift & monitoring |
| `behavioral-interview-writing` | Phỏng vấn hành vi, kỹ năng mềm | Phương pháp STAR, nhóm câu hỏi thường gặp, ví dụ trước/sau, chân thật (không bịa thành tích) |

## Quy trình đầy đủ (để tăng traffic)

```
1. Nghiên cứu   → blog-ideation-seo   (chọn chủ đề có nhu cầu + Content Brief)
2. Viết         → blog-foundations + skill chủ đề + skill dạng bài
3. Tiêu đề      → title-headline-writing
4. Review       → blog-review + skill review chuyên biệt
5. Đóng gói     → wordpress-publishing / markdown-authoring
6. Tăng traffic → content-optimization-distribution (refresh, internal link, phân phối)
```

## Cách hoạt động

- **Nghiên cứu trước khi viết:** dùng `blog-ideation-seo` để chọn chủ đề có nhu cầu tìm kiếm và tạo Content Brief. Đây là bước quyết định traffic.
- **Viết:** áp dụng `blog-foundations` trước để đặt nền (chân thật, giọng văn, cấu trúc, SEO, trích dẫn), rồi skill chủ đề (tin tức/Backend/tips, hoặc system design/LLD/DSA/ML system design/behavioral), rồi skill dạng bài (tutorial/listicle-comparison) nếu bài thuộc dạng đó.
- **Review:** áp dụng `blog-review` trước (quy trình + format báo cáo), rồi áp dụng skill review chuyên biệt để thêm tiêu chí riêng của loại bài.
- **Viết và review là cặp đối xứng.** Skill review kiểm tra chính các checklist mà skill viết yêu cầu — dùng để kiểm tra bài trước khi xuất bản.
- **Định dạng đầu ra:** sau khi có nội dung, dùng `wordpress-publishing` hoặc `markdown-authoring` để đóng gói bài ra định dạng đích. Hai skill này chỉ lo trình bày, không thay đổi nội dung.
- Mỗi skill có phần **Checklist** riêng, chạy cùng checklist nền tảng.
- Skill được kích hoạt tự động khi yêu cầu của người dùng khớp với phần `description` trong front-matter (`inclusion` mặc định), hoặc gọi thủ công qua `#` trong chat.

## Tùy chỉnh

Muốn đổi giọng văn, độ dài, hay quy tắc SEO cho toàn bộ blog, sửa `blog-foundations/SKILL.md`. Muốn đổi quy trình/format báo cáo review chung, sửa `blog-review/SKILL.md`. Muốn tinh chỉnh riêng một loại bài, sửa file SKILL.md tương ứng.
